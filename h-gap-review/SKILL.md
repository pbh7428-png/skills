# 누락·위험 검수 (기존 Plan 리뷰 + PRD/TRD 리뷰 통합)

이 검수는 **작성자와 분리된 에이전트**로 실행하는 것을 권장한다 (작성자와 같은 맥락이면 같은 맹점을 공유함).

## 파일 접근 규칙 (최우선) — 읽기 전용
- 모든 파일을 **읽기만** 한다. 파일 생성·수정·삭제, 코드 실행으로 파일 변경 금지.
- 문제를 찾아도 PRD/TRD를 **직접 고치지 않는다**. 수정 제안은 출력 표에만 쓴다.
- 결과는 대화창에만 출력한다 (파일 저장 없음).
- 가능하면 이 검수 세션은 `codex --sandbox read-only` 로 띄운다.

## 입력
- 검수 대상: `docs/PRD.md`, `docs/TRD.md` (또는 구현 계획)
- 기준: `docs/01_requirements_table.md`, `docs/interview.md`, `docs/02_data_check.md`

## 검수 항목 (이 순서로, 이것만)
1. **요구사항 누락**: 기준 문서의 각 요구ID/확정 조건이 PRD에 있는가 → 매핑 표, 빠진 ID 나열
2. **수용 기준 누락**: Must 요구마다 테스트 가능한 수용 기준이 있는가. 결과물 조건(노선 길이·간격·시간 등)이 빠지지 않았나
3. **Hard/Soft 오분류**: hard인데 soft로, 또는 HR이 언급한 불만이 아예 빠졌나
4. **MVP 위험**: MVP 범위가 90분 안에 end-to-end로 연결 가능한가. 과한 항목 지적
5. **인터페이스 위험**: 모듈 입출력 스키마가 고정돼 있어 병렬 개선 시 통합이 깨지지 않는가
6. **검증 공백**: baseline, 엣지셋, 대규모 테스트가 계획에 있는가

## 출력
| # | 항목 | 심각도(치명/중요/참고) | 근거(문서 위치) | 수정 제안 |
|---|---|---|---|---|

- **치명/중요만** 수정 제안을 구체적으로. 참고는 한 줄.
- 최대 10개. 문체·표현 지적 금지.

## 타임박스
5분. 넘으면 치명 항목만 출력하고 종료.
