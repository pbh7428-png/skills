# 누락·위험 검수 (기존 Plan 리뷰 + PRD/TRD 리뷰 통합)

이 검수는 **작성자와 분리된 에이전트**로 실행하는 것을 권장한다 (작성자와 같은 맥락이면 같은 맹점을 공유함).

## 파일 접근 규칙 (최우선) — 읽기 전용
- 모든 파일을 **읽기만** 한다. 파일 생성·수정·삭제, 코드 실행으로 파일 변경 금지.
- 문제를 찾아도 PRD/TRD를 **직접 고치지 않는다**. 수정 제안은 출력 표에만 쓴다.
- 결과는 대화창에만 출력한다 (파일 저장 없음).
- 가능하면 이 검수 세션은 `codex --sandbox read-only` 로 띄운다.

## 입력
- 검수 대상: `docs/PRD.md`, `docs/TRD.md` (또는 구현 계획)
- 기준: `docs/01_requirements_table.md`(덩어리 표, 구현 대상 아님, 범위 밖 보관함), `docs/interview.md`, `docs/02_data_check.md`
- 과제 README (기준값 대조용)

## 검수 항목 (이 순서로, 이것만)
1. **요구사항 누락**: 필수·산출물 덩어리와 인터뷰 확정 조건이 PRD에 모두 있는가 → 덩어리 ID 매핑 표, 빠진 ID 나열
2. **수용 기준 누락**: Must 덩어리마다 테스트 가능한 수용 기준이 있는가. 결과물 조건(데이터 검사 ③ 유형)과 성능·시간 제한이 빠지지 않았나
3. **필수 조건 완화**: 시간·개수·한도 같은 기준값이 README와 같은가. 다르면 HR이 명시적으로 바꾼 근거(인터뷰 위치)가 있는가. 근거 없는 완화는 **치명**
4. **범위 확장**: README에 없는 기능이나 범위 밖 보관함 아이디어가 Must·Should·MVP에 들어갔나. 들어갔으면 Won't 또는 개선 백로그로 옮기도록 제안
5. **Hard/Soft 오분류**: hard인데 soft로, 또는 HR이 언급한 불만이 아예 빠졌나
6. **문서 간 불일치**: 같은 항목의 값이나 확정/미정 상태가 PRD·TRD·인터뷰·데이터 검사 사이에서 다른가 (예: 한 문서는 "HR 합의 필요", 다른 문서는 "HR 수락")
7. **미정 항목 처리**: 가정·미정 목록의 항목마다 `내 제안`과 `HR 확인 여부`가 있는가. 제안 없이 "미정"으로만 남은 항목 지적
8. **MVP 위험**: MVP 범위가 제한 시간의 1/3 안쪽(예: 3시간이면 약 1시간)에 end-to-end로 연결 가능한가. 과한 항목 지적. PRD 2페이지·TRD 1페이지 초과도 여기서 지적
9. **인터페이스 위험**: 모듈 입출력 스키마와 전달 방식이 고정돼 있어 병렬 개선 시 통합이 깨지지 않는가
10. **검증 공백**: baseline, 엣지셋, 전체 데이터 테스트가 계획에 있는가. 성능·신뢰성 측정 조건(무엇을, 기준값, 측정 시작·끝, 언제 잴지)이 있고 MVP 첫 실행부터 재도록 돼 있는가

## 출력
| # | 항목 | 심각도(치명/중요/참고) | 덩어리 ID | 근거(문서 위치) | 수정 제안 |
|---|---|---|---|---|---|

- **치명/중요만** 수정 제안을 구체적으로. 참고는 한 줄.
- 최대 10개. 치명부터 정렬. 문체·표현 지적 금지.
- 덩어리와 관련 없는 지적(예: 문서 간 불일치)은 덩어리 ID를 `-`로 둔다.

## 타임박스
5분. 넘으면 치명 항목만 출력하고 종료.
