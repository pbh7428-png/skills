# PRD + TRD 작성

## 입력 (모두 있어야 시작)
- `docs/01_requirements_table.md` — README 추출 결과 (덩어리 표, 구현 대상 아님, 범위 밖 보관함, 모호 항목, 부록)
- `docs/interview.md` — HR 인터뷰 결과, 확정 조건, KPI 우선순위
- `docs/02_data_check.md` — 데이터 예외, 검증불가 조건
없는 파일이 있으면 무엇이 없는지 알리고 멈춘다.

## 파일 접근 규칙 (최우선)
- 입력 문서·README·데이터·코드는 **읽기만** 한다. 입력 3개 파일도 수정 금지 (누락을 발견하면 수정하지 말고 보고).
- 코드·스크립트 생성/수정, 명령 실행으로 파일 변경 금지.
- 결과물 저장은 `docs/PRD.md`, `docs/TRD.md` **두 파일만** 허용 (붙여넣기가 불가한 환경이라 이 둘만 예외).

## 바꾸지 않는 기준 (최우선)
- 덩어리 표에서 유형이 **필수·산출물**인 조건은 PRD에 그대로 옮긴다. 완화·삭제·"참고"로 격하 금지 (성능·시간 제한 포함).
- 바꿀 수 있는 경우는 HR이 명시적으로 바꾼 것뿐이다. 그때는 근거(인터뷰 위치)를 적는다.
- 지키기 어려워 보이는 필수 조건은 조건을 바꾸지 말고 TRD의 **위험**에 적고 대응 방법을 쓴다.

## PRD → `docs/PRD.md` (2페이지 이내)

1. **문제와 동기**: 왜 하는가. HR이 말한 현장 불만·페인포인트 포함 (5줄 이내)
2. **사용자와 사용 흐름**: 누가, 언제, 결과(화면·파일)에서 무엇을 보는가. 인터뷰에 없으면 가정으로 표시
3. **범위 (MoSCoW)**: **덩어리 ID 단위**로 쓴다
   - Must: 필수·산출물 덩어리 + HR이 필수로 확정한 조건
   - Should / Could: 선택 덩어리, HR 선호
   - Won't: 범위 밖 보관함의 README 제외 항목 + 보관함 아이디어. 제외 이유 명시
   - 보관함 아이디어는 Must·Should에 넣지 않는다
   - 출처: README 위치 또는 인터뷰 절(Q번호가 있으면 Q번호)
4. **제약**: Hard / Soft 구분
   - Soft는 처리 방식 명시: KPI로 측정 / 목적함수 패널티 / 향후 과제
5. **KPI**: 우선순위 순서, 정의(계산식), baseline 정의
6. **가정·미정 목록**: 항목마다 `내 제안 | HR 확인 여부(확정/미확인)`. 미확인이면 제안대로 진행하고 PASS 판정에서 구분한다
7. **엣지 케이스 처리 방침**: 데이터 예외, 수요 0/급증, 고장, 용량 초과 등 (표 1개)
8. **수용 기준**: **덩어리마다** 테스트 가능한 문장 1개 이상
   - 결과물 조건(데이터 검사 ③ 유형)과 성능·시간 제한 반드시 포함
   - 형식: `AC-{n} (G{id}): {입력/상황}일 때 {결과}가 {측정 가능한 기준}`

## TRD → `docs/TRD.md` (1페이지 제한)

1. **모듈과 입출력 계약**: 모듈 3~5개, 각 모듈의 입력/출력과 스키마(열 이름·타입) 고정
   - 맨 앞은 데이터 검증 모듈 (h-data-check 코드 재사용)
   - 맨 끝은 KPI 평가 모듈
   - 모듈 사이 전달 방식(메모리 / 파일)과 형식(CSV·JSON 등)을 적는다
2. **MVP 단계 vs 개선 단계**: 모듈별로 MVP에 쓸 단순 방법과 개선 방법을 표로
   - MVP 목표: 모든 모듈이 입력→출력 end-to-end 연결, 전체 데이터로 실행, 필수 수용 기준 통과
   - 개선은 입출력 계약을 유지한 채 모듈 안쪽만 바꾼다. `mvp`/`improved` 전환 설정은 **개선 구현이 실제로 있을 때만** 만든다
3. **알고리즘 선택**: 선택 + 대안 + 이유 (→ h-decision-log에 그대로 기록)
4. **테스트 전략**: 모듈 테스트 / e2e 테스트 / 수용 기준 테스트 / 데이터셋(정상 샘플, 엣지셋, 전체 데이터)
   - **성능·신뢰성 측정 조건**: 항목마다 `무엇을 | 기준값 | 측정 시작·끝 | 언제 잴지`. 성능은 MVP 첫 실행부터 매번 잰다
   - MVP 결과 KPI = baseline
5. **위험**: 지키기 어려운 필수 조건과 대응 방법 (조건을 완화하지 않는다)
6. **개선 백로그**: 우선순위, 예상 효과, 의존성, **병렬 가능 여부** 표시. 필수 수용 기준이 모두 통과한 뒤에만 착수

---

## 마지막: 자가 점검
1. **누락**: 덩어리 표의 필수·산출물 덩어리와 인터뷰 확정 조건이 PRD에 모두 있는지 매핑 표로 확인. 없으면 "누락 없음"과 근거
2. **완화 여부**: 필수 조건의 기준값(시간·개수·한도 등)이 README와 같은지 확인
3. **분량**: PRD 2페이지, TRD 1페이지를 넘으면 줄인다

## 금지
- 장황한 서술, 일반론
- TRD에 구현 코드 작성
- 입력에 없는 요구사항 추가 (필요하면 '가정'으로)
- README 필수 조건 완화 (HR 명시 변경 제외)
- 범위 밖 보관함 아이디어를 Must·Should에 넣기
