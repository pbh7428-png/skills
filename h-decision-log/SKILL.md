# 의사결정 로그 / 서술형 초안 / 질의응답 대비

목적: 작업 중 "왜"를 남겨 서술형과 사후 질의응답(설명력)에 대비한다.

## 파일 접근 규칙 (최우선)
- 쓰기는 `docs/decision_log.md` **하나만** 허용한다 (없으면 생성, 있으면 맨 아래에 추가). 기존 항목은 고치거나 지우지 않는다.
- 그 밖의 문서·README·데이터·코드는 **읽기만** 한다.
- 서술형 모드와 질의응답 대비 모드의 결과는 **대화창에만** 출력한다 (파일 저장 없음).

## 기록 형식
```
### D{번호} [{단계}] {결정 한 줄}
- 상태: {확정 / 가정(HR 미확인)}
- 근거: {README 위치 / 인터뷰 절 또는 Q번호 / 데이터 검사 결과 / 실험 결과}
- 대안: {고려했지만 안 고른 것}
- 이유: {왜 이걸 골랐나, 트레이드오프}
- 영향: {관련 덩어리 ID / KPI}
```

단계 태그: 요구사항 / 가정 / 범위 / 설계 / 알고리즘 / 검증 / AI오류수정 / 제출

특히 반드시 기록할 것:
- HR 인터뷰로 확정·변경된 조건
- HR에 한 제안과 HR의 답 (수락 / 수정 / 미확인)
- 가정으로 처리한 항목
- 범위에서 뺀 것(Won't)과 이유
- MVP vs 개선에 무엇을 넣었나
- 지키기 어려운 필수 조건과 대응 방법 (조건을 완화하지 않고 무엇을 바꿨나)
- 범위 밖 보관함 아이디어를 착수했다면 언제, 왜 (필수 덩어리 완료 여부 포함)
- **AI가 틀린 걸 발견하고 고친 사례** (어떻게 발견했는지 포함)

## 기록 모드 (기본)
사용자가 결정을 말하면 위 형식으로 1항목 추가한다. 짧게.

## 일괄 기록 모드
사용자가 "일괄 기록" 또는 "단계 정리"를 요청하면, 단계가 끝난 시점에 한 번에 기록한다.
- 권장 시점: HR 인터뷰 후 / PRD·TRD 후 / MVP 완료 후 / 제출 전
- `docs/` 아래 문서(추출표, 데이터 검사, 인터뷰, PRD, TRD 등)와 실행 결과를 읽고 **아직 로그에 없는 결정만** 위 형식으로 추가한다.
- 문서에서 근거를 찾을 수 없는 결정은 추측해서 채우지 않는다. 결정 한 줄만 적고 근거에 `[근거 없음 — 확인 필요]`로 표시한다.
- 추가한 항목 번호 목록을 대화창에 출력한다.

## 서술형 모드
사용자가 "서술형" 또는 "답안"을 요청하면 로그를 바탕으로 초안을 작성한다:
1. 문제 정의: 무엇을 왜 풀었나 (HR 불만·동기 포함)
2. 핵심 설계 결정 3~5개와 근거·트레이드오프
3. AI 활용 방식: 역할 분담, 맥락 부여, 병렬화
4. 검증 방법: 데이터 검사, 수용 기준 테스트, baseline 대비 KPI, 대규모/엣지 케이스, 잡아낸 AI 오류
5. 한계와 향후 개선

## 질의응답 대비 모드
사용자가 "질의응답" 또는 "예상 질문"을 요청하면 로그를 바탕으로 만든다:
- 예상 질문 최대 10개. "왜 이렇게 만들었나"류 질문을 우선한다 (알고리즘 선택, 범위에서 뺀 것, 가정 처리, 못 지킨 조건, AI 오류 대응).
- 질문마다 답 2~3줄과 근거 로그 번호(D{번호})를 붙인다.

## 공통 규칙
- 로그에 없는 내용은 지어내지 말고 "[로그 없음 — 확인 필요]"로 표시한다.
