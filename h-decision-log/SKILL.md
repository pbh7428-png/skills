# 의사결정 로그 / 서술형 초안

목적: 작업 중 실시간으로 "왜"를 남겨 서술형과 사후 질의응답(설명력)에 대비한다.

## 파일
`docs/decision_log.md` (없으면 생성, 있으면 맨 아래에 추가)

## 기록 모드 (기본)
사용자가 결정을 말하면 아래 형식으로 1항목 추가한다. 짧게.

```
### D{번호} [{단계}] {결정 한 줄}
- 근거: {README 위치 / 인터뷰 Q번호 / 데이터 검사 결과 / 실험 결과}
- 대안: {고려했지만 안 고른 것}
- 이유: {왜 이걸 골랐나, 트레이드오프}
- 영향: {어떤 요구사항/KPI에 영향}
```

단계 태그: 요구사항 / 가정 / 범위 / 설계 / 알고리즘 / 검증 / AI오류수정 / 제출

특히 반드시 기록할 것:
- HR 인터뷰로 확정·변경된 조건
- 가정으로 처리한 항목
- 범위에서 뺀 것(Won't)과 이유
- MVP vs 개선에 무엇을 넣었나
- **AI가 틀린 걸 발견하고 고친 사례** (어떻게 발견했는지 포함)

## 서술형 모드
사용자가 "서술형" 또는 "답안"을 요청하면 로그를 기반으로 초안을 작성한다:
1. 문제 정의: 무엇을 왜 풀었나 (HR 불만·동기 포함)
2. 핵심 설계 결정 3~5개와 근거·트레이드오프
3. AI 활용 방식: 역할 분담, 맥락 부여, 병렬화
4. 검증 방법: 데이터 검사, 수용 기준 테스트, baseline 대비 KPI, 대규모/엣지 케이스, 잡아낸 AI 오류
5. 한계와 향후 개선

규칙: 로그에 없는 내용은 지어내지 말고 "[로그 없음 — 확인 필요]"로 표시.
