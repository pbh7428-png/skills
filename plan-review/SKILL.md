# 실행 계획 독립 검토

계획 초안을 다른 에이전트가 검토하고, 원래 에이전트가 지적의 타당성을 확인해 필요한 수정을 반영한 뒤 사용자에게 제시한다. 에이전트는 작업을 맡아 수행하는 별도 AI를 뜻한다. 다른 회사나 다른 모델일 필요는 없으며 다른 스킬 없이 사용할 수 있다.

사용자 설명과 새 Markdown 문서는 기본적으로 한글로 쓰되 지정한 언어를 우선한다. 필요한 기술 용어는 쉬운 뜻과 함께 설명한다.

## 호출 시점과 실행 경계

- ‘계획을 검토해 줘’처럼 직접 요청받았거나, 작업 범위·순서·완료 확인 방법을 정식 실행 계획으로 제시할 초안이 준비되면 사용한다. 계획 모드에서도 현재 모드의 제한을 그대로 따른다. 이 스킬이 실행 모드를 전환하지는 않는다.
- 검토에 앞서 필요한 목적·범위 질문과 짧은 진행 안내는 할 수 있다. 사소한 편집을 위해 형식적인 계획을 새로 만들거나, 모든 진행 안내를 독립 검토하지 않는다.
- 앞으로 수행할 작업의 계획을 다룬다. 완성된 기획·설계 문서, 코드, 평가 결과 자체의 검토와 구분하고, 같은 계획에 `artifact-review`를 중첩 호출하지 않는다.
- 예를 들어 ‘파일 변환 도구를 어떤 순서로 구현·확인할지’는 이 스킬의 대상이고, ‘작성된 PRD/TRD와 평가 기준에 누락·모순이 있는지’는 결과물 검토의 대상이다. 한 문서에 둘 다 있으면 요청한 관점과 해당 부분을 구분하고 이미 검토한 같은 내용은 재사용한다.
- 원래 에이전트와 리뷰어는 계획 판단에 필요한 자료를 읽되, 검토를 이유로 구현·설치·배포나 프로젝트 상태 변경을 시작하지 않는다. 기존 계획의 검토만 요청받았다면 원본 파일을 바꾸지 않고 지적과 수정 제안을 보고한다. 계획 작성·수정까지 맡았다면 허용된 위치와 현재 모드 안에서 계획을 갱신한다.
- 사용자 결정·제외 범위와 프로젝트 규칙을 존중한다. 검토는 작업 범위나 권한을 추가하지 않는다.
- 정상적인 실행 경로가 막히거나 실패해 다른 도구·계정·인터페이스·경로로 우회하려면 먼저 막힌 이유·제안 방법·변경 범위와 영향을 설명하고 명시적 허가를 받는다. 작업 완료 요청이나 Full Access는 우회 허가가 아니다. 허가 대기 중에는 우회와 무관한 일을 계속할 수 있으며 상위 지침의 금지는 유지한다.

## 1. 검토할 초안과 근거 준비

기존 대화와 자료에서 다음을 정리한다. 이미 확인할 수 있는 내용은 다시 묻지 않고, 계획의 목적·범위·핵심 순서를 바꿀 정보가 빠졌을 때 질문한다.

- 사용자 요구, 확정된 결정, 중요한 제약과 제외 범위.
- 계획 초안, 관련 파일·데이터·기존 문서의 위치와 필요한 부분.
- 도구·권한·실행 환경에 관해 확인한 사실, 중요한 가정과 미정 사항.
- 주요 단계의 결과와 완료 확인 방법, 기존에 수행한 확인과 그 증거.

확정 사항과 가정을 구분한다. 자료의 존재를 사용 가능성으로 간주하지 않고, 계획한 검사를 이미 통과한 결과처럼 쓰지 않는다. 작성자의 자기 평가나 대화 전체를 기본 입력으로 넘기지 않되 필요한 사용자 결정은 생략하지 않는다. 리뷰어가 관련 원본을 추가로 읽을 수 있게 한다.

## 2. 별도 에이전트의 독립 검토

사용 가능한 에이전트 도구로 리뷰어 1명을 기본 호출한다. 새 대화 맥락에 필요한 자료와 아래 역할·판단 기준·반환 내용을 전달한다. 대화 이력 상속을 조절할 수 있다면 전체 이력을 넘기지 않는 방식을 사용한다.

**리뷰어의 역할**

- 계획 초안과 필요한 관련 원본을 직접 확인한다. 전달받은 요약만으로 결론을 확정하지 않는다.
- 파일과 프로젝트 상태를 변경하지 않는다. 실행·실험이 필요하다면 필요한 확인을 제안하고, 계획 검토를 이유로 직접 구현하거나 설치하지 않는다.
- 다시 다른 리뷰어를 생성하거나 검토 절차를 중첩 호출하지 않는다. 이미 리뷰어 역할로 이 스킬을 읽었다면 맡은 검토만 수행하고 반환한다.

**계획에 맞춰 확인할 기준**

- 사용자 요구와 범위가 맞는가? 요청하지 않은 기능·산출물·승인 절차를 추가했는가?
- 실제 파일·데이터·도구·권한·실행 환경을 고려했는가? 미확인 가정을 사실처럼 사용했는가?
- 먼저 해결할 불확실성과 선행 작업을 고려했는가? 실행 순서와 단계 간 연결이 타당한가?
- 주요 단계의 결과와 완료 확인 방법이 구체적인가? 필요한 검증을 빠뜨리거나 무관한 작업을 늘렸는가?
- AX·AI 작업이라면 핵심 데이터 확보·이용 가능성과 AI 품질 판단을 중요한 선택에 반영했는가? 관련 없는 계획에 이 항목을 강제하지 않는다.

작업에 실제로 중요한 위험과 실패 시 대응만 추가한다. 모든 계획에 상세 배포·운영·복구 절차나 고정 양식을 요구하지 않는다.

**반환할 내용**

지적은 **계획의 단계 또는 위치 / 문제 조건 / 영향 / 근거 / 개선 방향**을 가능한 범위에서 담는다. 실제 영향에 따라 **중대 문제 / 일반 문제 / 선택적 제안**을 구분하고, 확인된 문제와 추가 확인이 필요한 의문을 구분한다. 중대 문제는 핵심 요구 충족이나 실행 가능성 등에 큰 영향을 주는 문제다. 문제 개수·점수를 채우거나 문체·취향 차이를 결함으로 제시하지 않는다. 문제가 없다면 확인 범위와 남은 한계를 함께 밝힌다.

독립 에이전트를 사용할 수 없거나 호출에 실패하면 독립 검토 미실시와 남은 검토를 알린다. 다른 도구 등을 통한 우회는 사전 허가를 받는다. 허용된 자체 검토를 수행했다면 독립 검토와 구분하고, 자체 검토만으로 독립 검토 완료를 표시하지 않는다.

## 3. 지적 확인과 계획 수정

원래 에이전트는 지적을 검증할 주장으로 다룬다. 사용자 요구·원본 자료·확인 증거를 대조해 **반영 / 미반영 / 보류**를 판단한다. 자동 수용하거나 근거 없이 반박하지 않는다. 중요한 미반영·보류에는 이유와 영향을 남긴다.

맡겨진 범위 안에서 필요한 계획 수정을 수행하고, 바뀐 단계와 연결되는 순서·완료 기준·가정의 일관성을 다시 확인한다. 검토만 요청받았다면 원본 수정 대신 수정 방향을 제시한다. 범위를 넘어서는 결정이나 답이 필요한 중요한 선택은 사용자에게 확인하고, 답이 없으면 가정 또는 미정으로 남긴다. 검토를 통과시키려고 사용자 요구나 평가 기준을 조용히 낮추지 않는다.

기본은 **리뷰어 1명, 최초 검토 1회**다. 중대한 지적을 수정했거나 범위·구조·핵심 순서가 크게 바뀌면 바뀐 부분과 연결 지점 중심으로 **추가 독립 검토 1회**를 수행한다. 작은 문구 수정마다 재호출하지 않는다. 규모나 사용자 요청에 따라 조절하되 이유 없이 인원과 횟수를 늘리지 않는다.

동일 대상·동일 변경에 대한 검토는 재사용한다. 기본 제한에 도달하면 자동 검토 반복을 멈추고 미해결 문제·영향·다음 선택지를 보고한다. 해결되지 않은 문제를 통과로 표시하지 않으며, 이름만 바꿔 반복 제한을 우회하지 않는다. 이 제한은 필요한 수정과 일관성 확인을 생략하라는 뜻이 아니다.

## 4. 사용자에게 제시

수정된 계획, 검토로 바뀐 핵심 내용, 남은 중요한 질문과 가정·한계를 간결하게 전달한다. 이미 수행한 확인과 앞으로 할 확인을 구분하고, 독립 검토 여부를 정확히 알린다. 작은 문구 변경까지 별도 처리표·보고서를 만들거나 검토 대화 전체를 출력하지 않는다.

검토 완료는 사용자 승인이나 실행 검증 완료가 아니다. 계획만 요청받았다면 계획을 전달하고 마친다. 구현까지 이미 맡긴 작업이라면 검토를 새로운 일률적 승인 단계로 만들지 않고, 기존 요청·권한과 현재 실행 모드에 맞춰 다음 단계로 이어간다.
