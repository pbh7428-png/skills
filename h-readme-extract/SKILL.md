# README 전수 추출 → 덩어리로 묶기

목표: 요약이 아니라 **추출**이다. 원문의 조건을 하나도 빠뜨리지 않고 옮긴 뒤, 실제 작업에 쓸 수 있도록 **덩어리**로 묶는다.

- 전수 추출 표는 **빠뜨림 확인용**이다. 파일 맨 아래 부록에 둔다.
- 작업 기준은 **덩어리 표**다. 이후 단계(데이터 점검, 인터뷰, PRD/TRD, 구현, 검사)는 덩어리 ID로 참조한다.

## 파일 접근 규칙 (최우선)
- 과제 README·데이터·제공 파일은 **읽기만** 한다. 수정·삭제·이동·이름 변경·덮어쓰기 금지 (오타·서식 정리도 금지).
- 쓰기는 `docs/01_requirements_table.md` **새 파일 하나만** 허용. 원본 폴더 안에는 아무것도 만들지 않는다.

## 입력
- 과제 README (또는 사용자가 지정한 과제 문서)

## 절차

### 1. 전수 추출
README의 모든 요구사항·제약·조건·산출물을 아래 표로 작성한다.

| ID | 항목(한 줄 요약) | 유형 | 원문 인용(그대로) | 위치(섹션/줄) |
|---|---|---|---|---|

유형은 다음 중 하나:
- **산출물**: 제출해야 하는 것
- **필수(hard)**: 어기면 결과가 무효
- **선택(soft)**: 만족도·KPI에 영향, 어겨도 무효는 아님
- **모호**: 기준·범위·처리 방법이 불명확 → HR 질문 대상

규칙:
- 숫자, 단위, 범위가 들어간 문장은 **전부** 포함한다.
- "반드시, 단, ~경우, 제외, 최대, 최소, 이상, 이하, 금지, 고려, 우선" 이 들어간 문장은 **전부** 포함한다.
- 원문 인용은 바꾸지 말고 그대로 옮긴다. 요약은 '항목' 열에만 쓴다.
- 확신이 없으면 '모호'로 분류한다. 임의로 해석하지 않는다.

### 2. 누락 역검사
표를 완성한 뒤, README를 처음부터 다시 훑어 **표에 반영되지 않은 원문 문장만** 모두 나열한다.
- 각 문장이 정말 조건/요구가 아닌지(배경 설명 등) 판단해 표시한다.
- 조건이면 표에 행을 추가한다.

### 3. 덩어리로 묶기
전수 추출 행을 **한 번에 구현하고 한 번에 검사하는 단위**로 묶는다. 개수 목표는 두지 않는다.

묶는 원칙:
- 같은 출력 파일의 열 설명 → 그 파일 하나 (예: `plan.csv`의 열 11개 → "plan.csv 형식" 1개)
- 표의 각 행으로 나뉜 같은 규칙 → 규칙 하나 (예: 권역 A/B/C → "권역별 담당 허브" 1개)
- 계산 예시·이유 설명 문장 → 해당 규칙에 포함
- 화면 구성 항목 → 화면 하나. 단, 시간 제한처럼 **따로 재야 하는 조건**은 별도 덩어리로 분리할 수 있다.
- 시험 진행 규칙과 평가 기준 → 덩어리로 만들지 않고 아래 '구현 대상 아님'에 둔다.

| 덩어리 ID | 덩어리 이름 | 유형 | 핵심 조건(한 줄) | 포함 원문 ID |
|---|---|---|---|---|

- 덩어리 ID는 `G01`부터 붙인다.
- 유형은 1단계와 같은 4가지 중 하나다. 포함 행의 유형이 섞이면 가장 엄격한 것(필수 > 산출물 > 선택)을 쓰고, 모호한 행이 있으면 아래 모호 목록에도 올린다.
- 핵심 조건은 원문 내용만으로 쓴다. 해석·설계를 덧붙이지 않는다.
- **누락 확인:** 모든 전수 추출 행 ID는 덩어리 표 또는 '구현 대상 아님' 중 **정확히 한 곳**에 들어가야 한다. 빠지거나 두 곳에 들어간 ID가 없는지 마지막에 대조한다.

### 4. 구현 대상 아님 분리
지켜야 하지만 **만들 기능은 아닌 것**을 따로 모은다.
- 시험 진행 규칙: 제한 시간, HR 응답 범위, 외부 내용 붙여넣기 금지·직접 입력 등
- 평가 기준: 평가 항목과 보는 것

| 원문 ID | 내용(한 줄) | 구분(진행 규칙 / 평가 기준) |
|---|---|---|

### 5. 범위 밖 보관함
**README가 요구하지 않는 것**을 필수 작업과 섞이지 않게 따로 둔다.

1. README가 **명시적으로 제외한 것**을 원문 인용과 함께 적는다 (예: 다른 허브 차량 지원, 중간 재상차, 신호·정체 고려). 해당 문장이 덩어리에 포함된 행에 있으면 그 원문 ID를 함께 적는다.

| 제외 항목 | 원문 인용(그대로) | 원문 ID |
|---|---|---|

2. 작업 중에 떠오르는 **추가 기능 아이디어**를 적을 빈 표를 만들어 둔다. 이 스킬은 아이디어를 새로 지어내지 않고 표만 만든다.

| 아이디어 | 떠올린 시점 | 상태(보류/착수) |
|---|---|---|

- 규칙: 보관함의 아이디어는 **필수·산출물 덩어리가 모두 끝난 뒤에만** 착수한다. 착수하면 상태를 바꾼다.

### 6. 출력
`docs/01_requirements_table.md` 한 파일에 아래 순서로 저장한다.

1. 덩어리 표 (작업 기준)
2. 구현 대상 아님
3. 범위 밖 보관함 (제외 항목 + 아이디어 빈 표)
4. 모호 항목 (HR 질문 후보) — 아래 3열 형식으로 고정한다. 전수 추출 표의 행을 그대로 복사하지 않는다.

| 덩어리 ID | 모호한 점 | 근거 위치(섹션/줄) |
|---|---|---|

5. 부록: 원문 전수 추출 표 + 누락 역검사 결과 + 덩어리 누락 확인 결과

## 금지
- 요약으로 대체하지 말 것 (부록의 전수 추출 표는 반드시 남긴다)
- 원문에 없는 조건을 추가하지 말 것 (덩어리 표의 핵심 조건에도 원문에 없는 조건을 넣지 말 것)
- 해결책·설계 제안을 하지 말 것 (이 단계는 추출과 묶기만)
