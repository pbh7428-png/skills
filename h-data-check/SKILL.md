# 데이터 검사 (프로파일링 + 조건 대조)

원칙: 데이터를 **눈으로 훑지 말고 코드로 전수 검사**한다. 결과는 항상 "유형 / 건수 / 샘플 3행"으로 출력한다. "문제없어 보임" 같은 서술 금지. 이상이 있는 행은 샘플만이 아니라 **전부** `docs/02_data_issues.csv`에 남긴다.

## 파일 접근 규칙 (최우선)
- 원본 데이터 파일과 데이터 README는 **읽기만** 한다. 수정·삭제·이동·이름 변경·덮어쓰기 금지.
- 검사 코드는 원본을 읽기 모드로만 연다. `to_csv`/`to_excel` 등으로 원본 경로에 저장 금지, in-place 변경 금지.
- 정렬·형 변환·정규화·결측 처리가 필요하면 **메모리 상의 사본**에서만 한다. 정리된 데이터를 파일로 남기지 않는다.
- 쓰기 허용 범위: `scripts/profile_data.py`, `scripts/check_conditions.py`, `docs/02_data_check.md`, `docs/02_data_issues.csv`만.
- `docs/02_data_issues.csv`는 정제본이 아니라 **이상 목록**이다. 문제 행의 위치(파일·행번호·키)와 문제 열의 원본 값만 적는다. 행 전체 복사, 값 보정·정규화 결과 기록 금지.

## 입력
- 데이터 파일들
- 데이터 README (컬럼 명세)가 있으면 함께
- 2단계용: `docs/01_requirements_table.md` (h-readme-extract 결과)

## 1단계: 프로파일링 (조건표 없이도 실행 가능)
`scripts/profile_data.py` 를 작성·실행한다. 파일마다:
- **타입**: 열별 dtype, 숫자여야 할 열에 문자 혼입 여부
- **결측**: 열별 결측 수/비율
- **중복**: 완전 중복 행 수, 키(ID) 중복 수
- **범위**: 숫자 열 min/max, 음수·0·비현실 값
- **고유값**: 범주 열 고유값 목록(상위 20), 표기 변형(공백·대소문자·오타) 탐지
- **단위**: 값 분포로 단위 추정 (분/초, m/km 등), 데이터 README 명세와 비교
- **파일 간 참조**: 한 파일의 ID가 다른 파일에 존재하는지 (예: 수요의 정류장ID ∉ 정류장 목록)
- **명세 불일치**: 데이터 README에는 있는데 실제 없는 열, 명세 범위와 실제 범위 차이

찾은 이상 행은 `docs/02_data_issues.csv`에 `단계=1_프로파일링`으로 기록한다 (아래 "이상 데이터 목록" 참고).

## 2단계: 조건표 대조 (h-readme-extract 완료 후)
조건표의 각 행을 검사 코드로 변환해 `scripts/check_conditions.py` 로 실행한다.
- **위반**: 각 hard/soft 조건을 어기는 행
- **미분류(커버리지)**: README의 분류 규칙(시간대, 구역, 유형 등) 어디에도 해당하지 않는 행
- 조건 ID와 검사 결과를 1:1로 매핑해 출력

위반·미분류 행은 `docs/02_data_issues.csv`에 `단계=2_조건대조`로 기록한다.

## 3단계: 검증불가 조건 분리
코드로 바꾸지 못한 조건을 **반드시 따로** 나열하고 사유를 분류한다:
- ① 기준이 정성적 (예: "편의 고려") → HR 질문: 측정 기준
- ② 데이터에 근거 열이 없음 → HR 질문: 출처 또는 무시 여부
- ③ 결과물에 대한 조건 (예: "노선당 정류장 ≤15") → 수용 기준 테스트로 이관

검증불가 조건은 행이 아니라 조건이므로 CSV에 넣지 않고 md에만 적는다.

## 이상 데이터 목록 (CSV)
- 경로: `docs/02_data_issues.csv`
- 인코딩: UTF-8 BOM (`encoding="utf-8-sig"`) — 엑셀에서 한글이 깨지지 않게
- **한 줄 = 한 행의 한 가지 문제.** 한 행에 문제가 2개면 2줄로 적는다.
- 열 구성 (이 순서 그대로):

| 열 | 내용 |
|---|---|
| `단계` | `1_프로파일링` / `2_조건대조` |
| `조건ID` | 조건표 ID (예: R018). 프로파일링에서만 나온 문제는 빈칸 |
| `이상유형` | 결측, 중복, 범위, 타입혼입, 표기변형, 단위혼재, 참조실패, 명세불일치, 위반, 미분류 등 |
| `파일` | 원본 파일 이름 |
| `행번호` | 엑셀에서 보이는 줄 번호 (헤더=1, 첫 데이터 행=2). 열 자체 문제처럼 특정 행이 없으면 빈칸 |
| `키` | 그 행의 ID 값 (예: O000428) |
| `열` | 문제가 있는 열 이름 |
| `값` | 원본 값 그대로 (공란이면 빈칸) |
| `설명` | 무엇이 왜 문제인지 한 줄 |
| `처리제안` | `가정 처리` / `HR 질문` (아래 "처리 기준" 적용) |

- 담는 범위: 1단계 이상 행 + 2단계 위반·미분류 행. 정상 분류(예: 일반 주문)는 넣지 않는다.
- 생성 방식: 1단계 `profile_data.py`가 1단계 문제로 CSV를 만든다. 2단계 `check_conditions.py`는 `profile_data.py`의 검사 함수를 불러 1·2단계 문제를 함께 모아 **파일 전체를 다시 쓴다** (실행할 때마다 덮어쓰기 → 같은 줄이 쌓이지 않음).
- 건수 일치: 스크립트가 `조건ID/이상유형`별 줄 수를 화면에 출력한다. md 예외 표의 `건수`는 이 줄 수와 같아야 한다.

## 출력
1. `docs/02_data_check.md` — 맨 위에 CSV 경로와 총 줄 수를 적고, 이어서:
   1. 프로파일링 요약 표
   2. 예외 표: | 조건ID/유형 | 건수 | 비율 | 샘플 3행 | 제안(가정 처리 / HR 질문) | (전체 행은 CSV)
   3. 검증불가 조건 목록 (①②③ 분류)
   4. HR 질문 후보 (숫자 포함 형태: "운행시간 외 수요 120건(8%) — 제외? 별도 처리?")
2. `docs/02_data_issues.csv` — 이상 행 전체 목록 (위 형식)

## 처리 기준 (제안 열 작성 시)
- 기술적 정리 문제 + 소수 + 결과 영향 적음 → **가정 처리** (예: "결측 3건 제외")
- 비즈니스 의미가 있거나 결과를 바꿈 → **HR 질문**

## 금지
- 데이터 수정·삭제·정제본 저장 금지 (검사만 — 위 파일 접근 규칙). 이상 목록 CSV는 예외지만 위치와 원본 값만 담는다.
- 타임박스 10분. 초과 시 사소한 항목은 가정 목록으로 넘기고 종료
- 검사 코드는 이후 파이프라인 입구(검증 모듈)에서 재사용할 수 있게 함수로 작성
